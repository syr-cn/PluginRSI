Abstract

The harness surrounding a language model is a central determinant of agent performance. Recent methods optimize harnesses by searching over complete programs, where individual mechanisms are difficult to isolate and reuse. We introduce PluginRSI, which represents a harness as a composition of atomized plugins and organizes harness evolution around these plugins. Individual plugins are improved independently and accumulated in a shared library, then recombined into new harnesses at each iteration. PluginRSI improves over existing harness optimization methods across software engineering, command-line interaction, and question-answering tasks. The resulting harnesses retain their advantage when transferred to other solver models without further optimization. The evolved plugin library accelerates subsequent optimization from the initial harness, which helps faster and higher convergence on unseen tasks. These results show that accumulating reusable mechanisms provides an effective basis for continued harness improvement.

Approach

Prior harness optimizers rewrite the complete harness program at every step. Mechanisms stay coupled inside one implementation, so new ones are hard to explore in isolation, and rewriting can overwrite ones that already worked.

PluginRSI instead uses plugin-parameterized harnesses, H = 𝓗(W, 𝓟): a set of plugins (roles, tools, skills, memory), each a versioned package with a standard interface, plus a workflow W that decides when they run. Each iteration has two stages:

  1. Plugin mutation. Eight candidates run in parallel, each on its own balanced minibatch (10 solved, 10 unsolved). Each changes one plugin while everything else stays fixed; variants that improve the score are added to the library.
  2. Harness recomposition. The proposer selects plugins from the updated library and revises the workflow. The new harness replaces the incumbent only if it scores higher on the full held-in set.

Results

Ablation

Both stages matter: removing plugin mutation or harness recomposition drops the Kimi-K3 held-out rate from 69% to 57% and 59%. A plugin library by itself does little — adding one to Meta-Harness moves it from 63% to 64%.

Repair-scope control

Role · coder · 10/20 → 13/20
BeforeWork in short evidence loops… make the smallest plausible edit and add or update a focused regression test.
AfterFor a partial batch write, validation failure, transaction, cache update, or state reset, put the guard, rollback scope, or cleanup at the smallest sequence of persistent mutations that needs it.

Semantic source preservation

Skill · debugging · 10/20 → 13/20
BeforeMake the smallest implementation change that enforces the stated invariant; preserve unrelated APIs, ordering, types…
AfterDo not replace an invalid positional access with a fallback to a different input merely because it avoids the exception; decide whether the correct absent-source result is empty, a documented default, or an explicitly defined alternative.

Incremental evidence retrieval

Memory · experience bank · 10/19 → 14/19
BeforeStore every tool output and retrieve the top-k by lexical overlap, often re-surfacing evidence already in context.
AfterDeduplicate stored outputs, return only entries not yet delivered, and summarize recent unseen evidence with guidance for the next verification step.

Failure-aware terminal feedback

Tool · terminal · 10/20 → 14/20
BeforeExecute the command, convert output to text, truncate, return.
AfterInspect the full output for execution and test failures, including ones masked by a zero exit status, append recovery guidance, and flag when the same focused test fails with the same diagnostic again.

Accumulation and reuse

Over 15 steps the library grows from 75 to 132 plugins. Final candidates reach about 1,300 lines of code, compared with about 400 for Meta-Harness, while the workflow stays under 300 — the added complexity lives in reusable plugins rather than in the glue.

The evolved library also speeds up later searches. Starting again from the initial harness but with the evolved library reaches 69% held-out after two steps, versus 65% without it, close to the 70% reached by continuing from the evolved harness itself.
